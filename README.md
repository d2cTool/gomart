# Гофермарт — накопительная система лояльности

HTTP-сервис накопительной системы лояльности «Гофермарт»: регистрация и аутентификация пользователей, приём номеров
заказов, опрос внешней системы расчёта баллов и ведение накопительного счёта.

## Требования

* Go 1.26+
* PostgreSQL 13+
* внешний сервис расчёта начислений (`cmd/accrual/accrual_*`) — для полноценной работы начислений

## Запуск

```bash
go build -o cmd/gophermart/gophermart ./cmd/gophermart

./cmd/gophermart/gophermart \
  -a localhost:8080 \
  -d "postgresql://postgres:postgres@localhost:5432/praktikum?sslmode=disable" \
  -r http://localhost:8081
```

Бинарный файл системы расчёта начислений в репозитории не хранится: для прохождения автотестов положите его
в `cmd/accrual/` (файлы `accrual_linux_amd64`, `accrual_darwin_*`, `accrual_windows_amd64` из релиза
[go-autotests](https://github.com/Yandex-Practicum/go-autotests/releases)).

Схема базы данных создаётся автоматически при старте: миграции встроены в бинарный файл и применяются под
рекомендательной блокировкой PostgreSQL, поэтому одновременный запуск нескольких экземпляров безопасен.

### Конфигурация

| Параметр                  | Флаг | Переменная окружения     | По умолчанию     |
|---------------------------|------|--------------------------|------------------|
| Адрес и порт сервиса      | `-a` | `RUN_ADDRESS`            | `localhost:8080` |
| Адрес подключения к БД    | `-d` | `DATABASE_URI`           | — (обязателен)   |
| Адрес системы начислений  | `-r` | `ACCRUAL_SYSTEM_ADDRESS` | —                |
| Уровень логирования       | `-l` | `LOG_LEVEL`              | `info`           |
| Секрет подписи JWT        | —    | `JWT_SECRET`             | встроенный       |

Переменные окружения имеют приоритет над флагами. Если адрес системы начислений не задан, сервис работает без фонового
опроса и заказы остаются в статусе `NEW`.

## HTTP API

| Метод и путь                       | Назначение                              |
|------------------------------------|-----------------------------------------|
| `POST /api/user/register`          | регистрация и автоматическая аутентификация |
| `POST /api/user/login`             | аутентификация по паре логин/пароль     |
| `POST /api/user/orders`            | загрузка номера заказа (`text/plain`)   |
| `GET /api/user/orders`             | список заказов пользователя             |
| `GET /api/user/balance`            | текущий баланс и сумма списаний         |
| `POST /api/user/balance/withdraw`  | списание баллов в счёт оплаты заказа    |
| `GET /api/user/withdrawals`        | история списаний                        |

Токен аутентификации выдаётся в заголовке `Authorization: Bearer <token>` и дублируется в cookie `gophermart-auth`;
принимается любой из этих способов. Запросы и ответы поддерживают сжатие `gzip`.

## Архитектура

```
cmd/gophermart          точка входа
internal/app            сборка компонентов и управление жизненным циклом
internal/config         флаги и переменные окружения
internal/handler        HTTP-обработчики и маршрутизация
internal/middleware     аутентификация, gzip, логирование запросов
internal/service        бизнес-логика: пользователи, заказы, счёт
internal/repository/postgres  хранилище, транзакции и встроенные миграции
internal/accrual        клиент внешней системы расчёта начислений
internal/worker         фоновый опросчик системы начислений
internal/auth           выпуск и проверка JWT
internal/luhn           проверка номера заказа по алгоритму Луна
internal/models         доменные типы и ошибки
```

Ключевые решения:

* баллы хранятся целым числом сотых долей (`models.Points`), что исключает ошибки округления; в JSON тип
  сериализуется как обычное десятичное число;
* пароли хранятся в виде bcrypt-хешей;
* начисление баллов и списание выполняются в транзакциях (`SELECT ... FOR UPDATE`, `CHECK (current >= 0)`), повторный
  расчёт по заказу в окончательном статусе баллы не удваивает;
* фоновый опросчик забирает заказы пачками с `FOR UPDATE SKIP LOCKED` и обрабатывает их пулом горутин; при ответе
  `429 Too Many Requests` раздача заказов воркерам прекращается, а пауза из заголовка `Retry-After` выдерживается
  между проходами, поэтому пул не простаивает заблокированным и остаток очереди опрашивается после паузы;
* операции с БД повторяются при сетевых сбоях и ошибках соединения класса `08`.

## Тесты

Юнит-тесты:

```bash
go test ./...
```

Интеграционные тесты (реальный PostgreSQL и подставная система начислений) собираются по тегу `integration` и требуют
переменной окружения `TEST_DATABASE_URI`:

```bash
docker run -d --rm --name gophermart-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=praktikum -p 5432:5432 postgres:16-alpine

TEST_DATABASE_URI="postgres://postgres:postgres@127.0.0.1:5432/praktikum?sslmode=disable" \
  go test -tags=integration ./...
```

Каждый пакет интеграционных тестов работает в собственной схеме БД, поэтому их можно запускать параллельно.

Покрытие:

```bash
go test ./... -coverprofile=coverage.out && go tool cover -func=coverage.out
```

Текущее покрытие: ~63% по юнит-тестам и ~88% с учётом интеграционных.
